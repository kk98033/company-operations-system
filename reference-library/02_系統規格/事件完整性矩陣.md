# 事件完整性矩陣

> 版本：v1.0
> 日期：2026-08-21
> 程式權威來源：`backend/app/core/event_completeness.py`

## 1. 目的

所有成功業務異動、認證／Session 操作、權限拒絕與敏感讀取都必須留下可由 Request ID 串接的證據。一般列表與查詢不重複寫入業務 audit，會由 Phase 11.5 的 structured access log 記錄。

目前矩陣覆蓋：

- 57 個 mutating API：必須對應業務 audit、安全事件，或兩者。
- 5 個敏感讀取：audit 查閱、公司 Session 清單、附件下載、正式 PDF 下載、CSV 匯出。
- 新增 POST／PUT／PATCH／DELETE operation 後若未更新矩陣，測試立即失敗。
- 矩陣只記 event code，不保存 request body、Cookie、CSRF、raw Session token、密碼、Secret、完整 DSN 或附件內容。

## 2. 分層規則

| 類型 | 紀錄位置 | 例子 |
|---|---|---|
| 業務異動 | append-only `audit_logs` | `work_order.confirm`、`shipment.confirm`、`receipt.record` |
| 認證／權限 | append-only `login_security_events`（保留既有實體表名） | `login_succeeded`、`logout_succeeded`、`permission_denied` |
| Session 管理 | audit＋security event 同交易 | `session.revoke`、`session_revoked` |
| 敏感讀取 | append-only `audit_logs` | `work_order.attachment.download`、`document.pdf_download`、`operations.csv_export`、`audit.read` |
| 普通讀取 | Phase 11.5 structured access log | 一般清單、明細、搜尋與 dashboard |

## 3. 資料最小化與不可變性

- 未知登入只保存 HMAC credential fingerprint；成功登入後的事件只保存 organization、user、membership、internal Session UUID 與 Request ID。
- 權限拒絕只保存正規化 capability code，不保存 URL query 或 request body。
- 敏感下載只保存文件類型、內部 ID、筆數、byte size 或 SHA-256 等必要 metadata，不保存檔案內容。
- PostgreSQL trigger 拒絕 `audit_logs` 與 security event 的 UPDATE、DELETE、TRUNCATE。
- 業務資料、audit 與 security event 必須共用同一 transaction；事件保存失敗時不得假裝操作成功。

## 4. 已知邊界

- 帳號／membership 停用管理 API 尚未建立；未來建立該 command 時，必須在同一交易撤銷相關 Session 並加入本矩陣，否則 Gate 會失敗。
- Phase 11.5 才補每個 HTTP request 的 route template、status、duration 與安全 actor 摘要；本 Slice 不把所有 GET 塞入 `audit_logs`。
- 備份／還原事件由 Phase 11.9～11.12 實作後加入安全事件與營運告警。
