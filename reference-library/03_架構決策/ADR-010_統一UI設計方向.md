# ADR-010：統一 UI 設計方向

- 狀態：Accepted
- 日期：2026-08-05
- 決策者：使用者與開發端
- 相關 Slice：0.7、0.8，以及所有後續前端 Slice
- 詳細規格：[UI 設計系統與通用版型](../UI設計系統與通用版型.md)

## 1. 背景

介面比較頁提供三個方向：A 平面工業 ERP、B 現代桌面 ERP、C Bootstrap 企業版。公司系統需要長時間處理工單、製程、庫存、出貨及帳務，資訊密度與可擴充性比行銷網站式卡片更重要；同時，新版也不能複製 Windows XP 的大量工具列與擁擠表單。

## 2. 決策

正式介面採以下混合方向：

- 使用 A 的資訊架構：左側模組導覽、上方環境列、工業藍灰配色、密集資料表、明確狀態色。
- 使用 C 的表單清晰度：穩定欄距、分區標題、較充足的垂直間距、簡單按鈕層級。
- 只保留 B 的操作習慣：鍵盤可達、快捷鍵預留、返回清單時保留查詢／分頁／捲動位置；不複製舊式多層選單與滿版工具列。

具體限制：

1. 正式畫面只有一層主側欄；展開 248px，收合 72px。
2. 主要容器不使用浮卡陰影、玻璃模糊或大圓角；圓角只允許 0、2、4px。
3. KPI 只出現在總覽／工作台；清單、建立、編輯與詳細資料頁不重複顯示。
4. 查詢列以 `auto-fit` 換行；按鈕不得因 1280px／1366px 螢幕而被裁切。
5. 清單第一識別欄固定在左側；重要欄位排列在水平捲動前段。
6. 狀態必須同時有文字與顏色／左邊線，不能只用顏色辨識。
7. 比較頁 `/style-preview` 保留為決策證據，不視為正式元件，也不得在裡面再建立第二個正式側欄。

## 3. UI 框架決定

目前正式基準以專案自己的 CSS Design Tokens 與小型 React 共用元件實作，不導入 Bootstrap。架構原先預定 Ant Design，修正為「未來可選的底層元件來源」：若後續因日期選擇器、複雜表格或無障礙元件而導入 Ant Design，必須套用本專案 Tokens 與版型，不得讓元件庫的預設卡片、圓角、間距或導覽取代 ADR-010。

不允許同時導入兩套完整 UI framework。

## 4. 影響

### 正面

- 產品導覽可擴充到報價、工單、生產、庫存、出貨、計價與請款。
- 員工在 1366×768 等公司常見桌面尺寸仍能看到重要欄位與動作。
- 表單比傳統 ERP 清楚，同時避免常見 AI Dashboard 的浮卡感。
- 後續頁面可直接使用相同的頁首、篩選、表格、狀態及表單分區。

### 成本

- 導入第三方元件時需要主題整合，不能直接使用預設視覺。
- 固定第一欄、表格密度及窄視窗行為需要專門測試。
- 所有新頁都要先選擇既有版型；例外版面需在 PR／進度紀錄說明原因。

## 5. 驗證

- 共用元件測試：頁首、KPI、狀態、表格固定欄及側欄收合。
- 版型測試：總覽有 KPI，清單／表單／詳細資料沒有 KPI。
- 人工尺寸：1920×1080、1366×768、1280×720，以及窄視窗降級。
- 鍵盤：Tab 順序、焦點可見、Enter／Space 操作及跳到主要內容。
- 規格一致性：以 `docs/UI設計系統與通用版型.md` 的檢查表驗收。
