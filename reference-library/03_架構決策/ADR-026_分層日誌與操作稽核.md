# ADR-026：分層日誌與操作稽核

> 日期：2026-08-20
> 狀態：Accepted

## 決策

1. 不把所有 request 塞進 `audit_logs`；分成不可變業務 audit、append-only 認證／資安事件、集中式 HTTP access／application log。
2. 所有成功業務異動與敏感讀取必須有可歸責 audit；登入、登出、Session 取代／撤銷、權限拒絕與備份／還原另有安全事件。
3. 每個 HTTP request 以 server Request ID 串接 route、status、duration、actor／Session reference 與錯誤類別；不保存 body、Cookie、CSRF、密碼、Secret、完整 DSN 或檔案內容。
4. 未知登入只保存 HMAC 指紋；成功登入後才保存可識別 actor。來源 IP／User-Agent 以可信 proxy 後的最小化摘要或 HMAC 指紋保存。
5. log 權限、保留、封存與刪除各自明確；一般操作員不可修改或清除。

## 原因

業務 audit 要能重建交易；security log 要能偵測攻擊；access log 要能追蹤每次 request。三者目的與保存量不同，混在一起會降低可查性並增加個資與儲存風險。
