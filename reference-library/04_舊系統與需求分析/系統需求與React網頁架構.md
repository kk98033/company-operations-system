# 印刷業整合管理系統翻新：需求盤點與 React 網頁架構

版本：初稿 v0.1
盤點來源：2 支操作需求影片、18 張舊系統畫面、PowerBuilder 6 專案與舊資料庫檔案
原則：本文件把「畫面已確認」與「仍需訪談確認」分開，避免直接把舊畫面原樣搬到新系統。

## 1. 系統定位

這是一套印刷／紙器加工公司的內部 ERP，主流程為：

> 客戶與基礎資料 → 建立訂單／製程傳票 → 排定加工與交期 → 出貨 → 計價／報價 → 應收帳款與報表

舊系統主選單可確認的模組：

- 基本資料
- 基礎設定
- 原料管理
- 製程傳票
- 報價單
- 帳款管理
- 系統管理

## 2. 使用角色（建議）

| 角色 | 主要工作 |
|---|---|
| 業務／接單 | 客戶查詢、建立訂單、查歷史訂單、報價 |
| 生管 | 製程傳票、排程、加工條件、交期與進度 |
| 現場人員 | 查看工單、回報生產數量／損耗／完工 |
| 倉管／出貨 | 原料、成品、出貨單、備品量 |
| 會計 | 計價、應收、收款、對帳、帳齡 |
| 主管 | 儀表板、訂單／產能／營收／逾期分析 |
| 系統管理員 | 使用者、角色權限、流水號與系統參數 |

小公司可由同一位員工兼任多個角色，權限仍應分開設定。

## 3. 核心功能需求

### 3.1 首頁儀表板

- 今日／本週待交訂單
- 生產中、待出貨、已逾期數量
- 待報價、待計價、未收款金額
- 快速建立訂單、出貨、報價
- 近期操作與待辦提醒

### 3.2 客戶管理

舊畫面已確認欄位：

- 客戶代碼、名稱、簡稱、統一編號
- 負責人、聯絡人、電話、電話 2、傳真
- 縣市、郵遞區號、地址
- 呼叫器、行動電話（新系統建議整併為多筆聯絡方式）
- 每筆合計取整數、稅額調整等計價設定

新系統建議：

- 客戶列表、全文搜尋、進階篩選
- 客戶詳情分頁：基本資料、聯絡人、地址、歷史訂單、報價、出貨、帳款
- 信用額度、付款條件、發票資訊、停用狀態
- 客戶資料匯入／匯出 Excel

### 3.3 基礎與加工設定

舊畫面已確認：

- 楞浪種類與價格
- 上光種類與價格（PP 亮／霧、UV、PVA、真空、金油、PET、雙面 UV 等）

建議統一為「加工項目」主檔：

- 類別、代碼、名稱、單位、單價
- 計價方式（按數量、面積、固定費、級距）
- 有效期間、啟用狀態
- 紙材、紙張規格、印色、刀模、版材等其他主檔

### 3.4 訂單管理

舊畫面已確認欄位：

- 傳票號碼、建檔日期
- 客戶名稱
- 訂貨名稱／品名
- 訂購數量
- 客戶訂單編號
- 交貨日期／異動日期

必要功能：

- 訂單列表：日期、客戶、狀態、交期、關鍵字複合查詢
- 建立、複製、修改、作廢訂單
- 一張訂單多個品項
- 品項規格、尺寸、數量、備品量、單價、備註與附件
- 訂單狀態：草稿、已確認、製作中、部分出貨、已完成、取消
- 歷史訂單查詢與一鍵複製重製
- 交期與異動紀錄
- 重要欄位變更留存操作人與時間

### 3.5 製程傳票／工單

影片與畫面可確認舊系統以製程傳票為中心，包含紙張／尺寸、印刷色彩、加工與數量等密集欄位。

建議新系統拆成清楚區塊：

- 基本：傳票號、客戶、品名、訂單、交期
- 規格：成品尺寸、展開尺寸、紙材、紙張規格、印色
- 紙張：紙別／紙種、磅數、紙廠／廠別，且需區分「面紙、底紙」；部分工單只有面紙
- 印版：新版或沿用舊版；建立新版時需記錄勾選狀態／版別（實際名稱待確認）
- 印刷：印刷尺寸（影片例：三開）與開數
- 數量：訂購量、加放量、備品量、生產量、良品、損耗；印刷數量需依開數及加放自動換算（影片例：1,400 + 100，加工數量 1,500）
- 製程：印刷、上光、裱浪、軋型／刀模、糊盒等步驟
- 外包：加工廠商、送出日、預計回廠日、費用
- 備註與附件：刀模圖、樣品照、客戶檔案
- 版本／異動歷程
- 列印製程傳票（保留目前紙本格式或重新確認版型）

### 3.6 生產進度

- 看板：待排程、待生產、生產中、待外包、待檢驗、完成
- 依機台／製程／交期排程
- 現場快速回報開工、完工、良品與損耗
- 逾期與缺料提示
- 訂單、工單、出貨狀態連動

### 3.7 原料與庫存

舊主選單含「原料管理」，細節仍需再確認：

- 原料／紙材主檔
- 入庫、領料、退料、盤點與調整
- 即時庫存與安全庫存
- 依工單預留／扣料
- 批號、供應商、成本（是否需要需訪談確認）

### 3.8 出貨管理

舊畫面已確認：

- 出貨日期、出貨單號、客戶名稱
- 訂貨名稱、出貨量、備品量、單價、價格小計
- 客戶訂單編號、備註
- 可依日期＋客戶代號或出貨單號查詢
- 有訂單、瀏覽、報表分頁

新系統必要功能：

- 由訂單／完工品建立出貨單
- 支援分批出貨與出貨餘量
- 出貨單列印
- 出貨查詢、作廢、重印
- 出貨後回寫訂單狀態並產生待計價資料

### 3.9 報價與計價

舊計價畫面可確認：

- 計價日期、序號、傳票號碼、出貨單號
- 客戶、品名、數量、總計、備註
- 明細內容、數量、價格、小計
- 常見費用：印刷、版費、刀模費

新系統建議：

- 報價單版本管理與有效期限
- 從歷史訂單／報價複製
- 材料、印刷、加工、版費、刀模費、運費、其他費用明細
- 自動小計、稅額、總計、折扣與四捨五入規則
- 報價轉訂單、出貨轉計價
- PDF／列印與 Excel 匯出

### 3.10 帳款管理

- 由已計價／出貨資料建立應收
- 對帳單、發票號碼、付款條件
- 收款登錄、沖帳、折讓與呆帳
- 未收、逾期、帳齡報表
- 客戶別應收明細

### 3.11 報表

- 訂單、出貨、報價／計價、應收報表
- 客戶別／期間別營收
- 交期達成率、製程損耗
- 原料庫存與異動
- 畫面篩選結果可匯出 Excel

### 3.12 系統管理

- 使用者、角色、功能與資料權限
- 系統流水號設定
- 公司、稅率、付款條件與列印設定
- 操作稽核紀錄
- 資料備份／還原與匯入紀錄

## 5. React 技術架構建議

React 只負責前端，不能直接安全地連舊資料庫，仍需後端 API。

```text
React Web
  ↓ HTTPS / REST API
Backend API
  ↓
New SQL Database
  ↑
One-time migration / reconciliation
  ↑
PowerBuilder + PBCT.DB
```

建議前端：

- React + TypeScript + Vite
- React Router
- TanStack Query（伺服器資料與快取）
- React Hook Form + Zod（表單與驗證）
- TanStack Table（密集表格、排序、篩選）
- Tailwind CSS + shadcn/ui 或 MUI（二擇一）
- Vitest + React Testing Library + Playwright

後端可選 Node.js（NestJS）或 ASP.NET Core；資料庫建議 PostgreSQL 或 SQL Server。若公司既有維運環境偏 Microsoft，ASP.NET Core + SQL Server 會較順；若團隊以 JavaScript 為主，NestJS + PostgreSQL 較一致。

## 7. 舊資料可否抽取

初步結論：**很有機會，但不能直接把 `.DB` 副檔名當成一般資料庫開啟。**

已找到：

- PowerBuilder 6 執行環境與 ODBC 元件
- 原始 PowerBuilder Library：`.pbl`
- 編譯後元件：`.pbd`
- 主程式：`uv.exe`
- 疑似正式資料庫：`pbct/uv_rar/PBCT.DB`（約 4.2 MB）
- 其他 `data_print.db`、列印資料庫與備份版本

下一步應在副本上：

1. 判定 `PBCT.DB` 實際引擎與版本（很可能是舊式 SQL Anywhere／Watcom，但需驗證）。
2. 從 `sqlca.scr`、ODBC 設定、PowerBuilder source 尋找連線字串與資料表名稱。
3. 用相容引擎唯讀掛載並匯出 schema 與 CSV。
4. 建立舊欄位 → 新欄位 mapping。
5. 做筆數、金額、訂單與出貨餘量對帳。

絕對不要直接在唯一舊檔上升級、修復或寫入。

## 8. 第一階段 MVP

建議先做最能串起營運的範圍：

1. 登入與角色權限
2. 客戶與加工／紙材主檔
3. 訂單
4. 製程傳票與列印
5. 生產進度
6. 出貨
7. 基礎計價
8. 舊客戶與歷史訂單資料移轉

原料精細成本、完整會計、進階排程與主管分析可排第二階段，避免首版一次承擔所有未知規則。

## 9. 需向使用者確認的規則

- 實際使用者與各自權限
- 從接單到出貨的每個狀態及可退回規則
- 製程種類、順序是否可由每張工單自訂
- 加放、備品、損耗的計算方式
- 報價／計價公式、最低價、取整與稅額規則
- 分批出貨、退貨、補貨如何處理
- 原料是否需要批號、成本與採購管理
- 舊紙本傳票、出貨單、報價單必須保留哪些版型
- 「紙廠／廠別」及「新版勾選」在公司內部使用的正確名稱
- 是否需要條碼／QR Code、手機或平板現場回報
- 舊資料需保留多少年，以及是否所有歷史單據都需可編輯
