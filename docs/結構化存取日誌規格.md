# 結構化存取日誌規格

> 版本：v1.0
> 完成日：2026-08-21
> 狀態：Phase 11.5 已接入全域 middleware；中央雲端收集與通知 channel 留在 11.8

## 1. 一個 request，一筆安全 JSON

每個 HTTP request 完成或發生未預期例外時，`app.access` 都輸出一行 JSON。它和交易式業務 audit、append-only security event 是三個不同用途：

| 層 | 用途 | 保存內容 |
|---|---|---|
| Access log | 流量、狀態碼、延遲與故障搜尋 | 每個 request 的安全摘要 |
| Security event | 登入、登出、Session、權限拒絕 | 資安事件與 Request ID |
| Business audit | 誰對哪筆公司資料做了什麼 | 同交易 before／after 最小差異 |

Access log 不能取代 audit，也不塞入資料庫交易；業務 rollback 不應讓 4xx／5xx access evidence 消失。

## 2. 固定 allowlist

| 欄位 | 語意 |
|---|---|
| `timestamp` | UTC ISO-8601 log 時間 |
| `event` | 固定 `http_access` |
| `request_id` | 每次由 server 產生的 UUID，與 response／audit／security event 關聯 |
| `method` | HTTP method |
| `route` | FastAPI route template；404 固定 `<unmatched>`，不記實際 path |
| `status_code` | response status；未預期例外記 500 |
| `duration_ms` | monotonic clock 計算的毫秒數 |
| `response_size_bytes` | 只讀安全的 `Content-Length`；未知時 `null`，不 buffer response |
| `slow_request` | `duration_ms >= 1000` |
| `error_code` | 穩定 public error code；成功為 `null` |
| `organization_id` | 已通過 Session 驗證時的公司 UUID |
| `user_id` | 已通過 Session 驗證時的內部 user UUID |
| `organization_member_id` | 已驗證 membership UUID |
| `session_id` | 可取得時的內部 Session UUID，不是 raw Cookie |

程式只從這份 allowlist 建 JSON，不序列化 Request、Response、Pydantic model、exception、ORM object 或 headers。

## 3. 明確禁止內容

以下內容不得出現在 access／application log：

- 實際 URL path 參數、query string、request／response body。
- `Cookie`、`Set-Cookie`、CSRF、Session raw token／digest、Authorization。
- 登入代號、姓名、Email、電話、地址、統編、客戶或報價／工單內容。
- 密碼、hash、Secret、DSN、環境變數值、附件或 PDF bytes。
- 未過濾的 exception message、SQL statement 或 parameters。

404 使用 `<unmatched>`，因此刻意把敏感字串放入不存在的網址也不會落 log。422 只記 `VALIDATION_ERROR`，不記使用者送來的錯值。

## 4. Severity 與查詢

- 2xx／3xx：`INFO`。
- 4xx：`WARNING`。
- 5xx：`ERROR`。
- 超過 1 秒：至少 `WARNING`，並設定 `slow_request=true`。

中央 log 可直接以 JSON 欄位查詢：

- `status_code >= 500`：服務錯誤；以 `request_id` 回查 application error、security event 或 audit。
- `status_code in (401,403,429)`：登入失效、Origin／CSRF、權限或限流趨勢。
- `status_code in (409,422)`：狀態衝突或輸入問題，用 route 聚合，不查看輸入內容。
- `slow_request=true`：找慢 route，再由 metrics／DB 查詢工具分析。

初始告警門檻由 11.8 以實際流量校準：5 分鐘內 5xx 至少 5 次或比例 2%、401／403／429 明顯高於基線、核心 route p95 超過 1 秒、連續 backup job 失敗。尚未設定通知 channel 前不得宣稱告警已啟用。

## 5. Proxy 與來源位址

目前 access log 刻意不記 client IP 或 User-Agent，也不信任 `X-Forwarded-For` 等轉送值，所以外部 caller 無法偽造來源進入正式 log。11.8 固定 Caddy／load balancer topology 後，才可設定明確 trusted proxy 數量／網段並增加經 HMAC／遮罩的網路分類；不得直接相信任意 forwarded header。

本機與正式 app 都輸出 JSON message；test 環境保留 logging propagation 以便 `caplog` 驗證。正式中央 log collector 只收 stdout／stderr，不由 App 持有額外 log service 帳密。

## 6. 自動守門

後端測試固定驗證：

1. route parameter／query canary 不落 log。
2. 404、422、500 的 route 與 error code 安全且 Request ID 一致。
3. 已驗證 Session 只加入四個內部 actor reference。
4. 每個 request 只產生一筆 access event。
5. JSON top-level 欄位不能超出 allowlist。

新增 access 欄位前必須先更新本文件、privacy review 與 canary tests，不能把方便除錯當成保存個資／Secret 的理由。
