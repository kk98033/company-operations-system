# ADR-013：舊系統全量資料匯入範圍

- 狀態：Accepted
- 日期：2026-08-07
- 決策者：使用者（代表公司需求）
- 對應：P0-10、MIG-001～MIG-004、Import I-1～I-8

## 1. 背景

舊系統已匯出 106 個 CSV，包含客戶、協力廠、工單、製程、完工存貨、出貨、計價、應收與收款等資料。使用者指定：可以的話全部匯入，不只保留近年資料。

## 2. 決策

1. 匯入目標不限年份，已結與未結資料都在範圍內；可取得的附件也納入。
2. 「全量」不等於把每個舊欄位強塞新版正式表，而是每個來源檔、資料表與資料列都有可核對的最終去向。
3. 去向分為四類：
   - 可正確 mapping 的新版正式業務資料。
   - 已停用、新版不再編輯或無法完整還原事件的只讀歷史封存。
   - 重複或合併資料，保留來源 mapping 和決議原因。
   - 亂碼、缺關聯、型別不明或無法安全轉換的例外資料，進 staging／error quarantine 等待人工處理。
4. 任何來源資料都不可靜默丟棄；核對報告的四類總數必須與來源邏輯資料筆數一致。
5. 匯入仍按 domain 分批進行，每批先 dry-run、編碼檢查、關聯核對、公司抽樣，通過後才 apply；不將全量匯入寫成一個大腳本。
6. 舊帳號密碼不匯入；帳號在新系統重建。

## 3. 驗收條件

- 106 個來源 CSV 都在 source manifest 且有雜湊、檔案大小、邏輯筆數與讀取狀態。
- 每個 domain 輸出新增、更新、只讀封存、合併／重複、警告與錯誤筆數。
- 客戶、工單、存貨、出貨、計價與帳款的關聯鏈可追回原始主鍵。
- 同一來源完全重跑不新增重複正式資料。
- 公司簽認筆數、數量、金額與例外清單後，才可正式切換。

## 4. 重新評估條件

只有法令、個資保留規則、來源毀損或公司後續明確排除特定資料類型時，才能縮小範圍，並必須新增決策與排除報告。
