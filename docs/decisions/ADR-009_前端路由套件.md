# ADR-009：前端路由套件改採 TanStack Router

- 狀態：Accepted
- 日期：2026-08-04
- 決策者：專案開發者（待公司技術負責人最終確認）
- 相關需求：Phase 0 前端骨架、頁面導覽
- 相關 Slice：0.6、0.7、0.8

## 背景

原架構指定 React Router。2026-08-04 初始化新專案時，`npm audit` 顯示當時可取得的 React Router 版本無法同時避開兩組 high severity 公告：較舊版本受 XSS／open redirect 公告影響，而新版 `7.12.0` 至 `<8.3.0` 受 unstable RSC CSRF 公告影響；公告列出的 `8.3.0` 修補版當時尚未發布到 npm registry。

雖然本系統目前只做 SPA，且不使用 RSC，新的內部公司系統仍不應以已知 high advisory 作為起始 lockfile。

## 選項

### 選項 A：暫時保留 React Router

- 作法：使用目前可取得版本並記錄未使用受影響功能。
- 優點：符合原架構名稱，團隊熟悉度較高。
- 缺點：`npm audit` 保留 high advisory；未來容易忘記升級。
- 資料／移轉影響：無。

### 選項 B：改採 TanStack Router

- 作法：使用 TanStack Router，鎖定避開已知受污染版本的乾淨版本，並維持 SPA 架構。
- 優點：目前可建立零已知 npm audit 弱點的 lockfile；型別安全路由適合後續大量業務頁面。
- 缺點：團隊需熟悉不同 API；未來若更換仍有轉換成本。
- 資料／移轉影響：無。

### 選項 C：自行以 History API 實作

- 作法：不使用第三方 router，只實作目前首頁與 404。
- 優點：零 router 依賴。
- 缺點：後續巢狀版面、參數、權限與導覽防護會重複造輪子，不適合完整管理系統。
- 資料／移轉影響：無。

## 決定

採用選項 B。`@tanstack/react-router` 必須鎖定在 `>=1.169.9` 的乾淨版本，並以 lockfile 固定實際版本。不得使用供應鏈事件已確認的 `1.169.5` 或 `1.169.8`。

切換時必須從乾淨 lockfile 重裝，確認 dependency tree 不含 `@tanstack/setup`、Git URL 或 `router_init.js`，並通過 `npm audit`、lint、typecheck、unit test 與 production build。

參考證據：

- React Router GHSA-2w69-qvjg-hvjx：<https://github.com/remix-run/react-router/security/advisories/GHSA-2w69-qvjg-hvjx>
- React Router GHSA-qwww-vcr4-c8h2：<https://github.com/advisories/GHSA-qwww-vcr4-c8h2>
- TanStack 供應鏈事件 GHSA-g7cv-rxg3-hmpx：<https://github.com/advisories/GHSA-g7cv-rxg3-hmpx>

## 影響

- 架構：將前端 router 從 React Router 改為 TanStack Router；React、Vite、FastAPI 與 PostgreSQL 不變。
- 資料表：無。
- API：無。
- UI：路由定義與 Link 元件改用 TanStack API，畫面資訊架構不變。
- 測試：所有路由必須有 rendering／404 smoke test；每次依賴更新要執行 `npm audit`。
- 移轉：尚無已上線前端，因此沒有使用者資料或 URL 相容移轉。
- 維運／成本：增加一項 ADR 與版本安全檢查，降低以已知 high advisory 起步的風險。

## 回復或重新評估條件

若 TanStack Router 未來不再維護、出現無可用修補版的高風險公告，或團隊確定以另一 router 作為標準，可新增 ADR 取代本決策。路由定義應集中，避免頁面直接依賴過多 router-specific API，以降低替換成本。
