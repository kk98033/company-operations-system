# Gmail 附件需求逐項對照

> 文件版本：v1.0  
> 日期：2026-08-08  
> 用途：把公司提供的報價單、工單與系統修改附件逐項連到需求 ID、實作 Slice 與驗收方式；本文件是 Phase 3／4 開發前的附件契約，不代表正式業務功能已完成。

> 2026-08-09 公司確認：新版 UI 嚴格維持本契約的欄位、分區、順序、單頁操作及列印內容；畫面使用現代工業 ERP 與 RWD，不逐像素複製 Windows XP。列印 9 道製程仍是尚未實作的 Phase 4 契約，不誤報為目前已有功能。

## 1. 證據判讀規則

| 附件類型 | 用途 | 不可誤用 |
|---|---|---|
| 無註解建檔稿 | 確認欄位、區塊、排列與文件方向 | 不自行補上附件沒有的必填、預設值或欄位 |
| 註解稿 | 確認自動帶入、格式、控制元件與公司明示規則 | 「樣式範例」只代表控制元件外觀，不延伸成新業務欄位 |
| 範例稿 | 建立 UAT／列印比對案例 | 客戶、品名、金額、數量及勾選結果不是系統預設值 |
| 列印稿 | 定義紙張方向、列印內容與不應出現的操作元件 | 編輯按鈕、輸入框外觀不得印進正式文件 |
| 系統修改圖 | 定義查詢、刪減功能與備份改善 | 不因舊畫面仍存在就重建已要求刪除的設定頁 |

若附件內容與既有整理稿不同，以公司明確註解和可見樣張為優先；仍有歧義的項目回到 `04_開工前確認清單.md`，不得由程式自行定案。

## 3. 報價單建檔契約

### 3.1 文件與客戶資料

- 頁首操作依公司稿保留「另存新檔、存檔、取消、列印」；正式功能權限與狀態由 Slice 3.3／3.6 控制。
- 公司名稱／Logo、電話、傳真、地址與 Email 來自公司設定，不寫死在 React 頁面或列印模板。
- 輸入客戶編號後，自動帶入客戶名稱、聯絡人、電話、傳真及地址；報價確認時保存文件快照。
- 報價日期預設公司當日且允許修改。
- 註解稿顯示舊候選為「年月日＋2 碼流水」，例如 `26042701`；使用者後續已在 P0-09／ADR-018 簽認新版 `QUO-YYYYMMDD-SS`，附件範例只作舊資料對照。

### 3.2 報價明細與備註

- 一張報價可有多筆明細；新增明細時序號依 01、02、03 連續顯示，刪除或重排後規則必須有測試。
- 每筆明細欄位依序為：序號、品名、尺寸、紙質、顏色、上光、版費、刀模費、數量、單價、附註。
- 單價至少顯示兩位小數；版費與刀模費為獨立金額欄位，不合併進單價。
- 文件底部有整張報價的備註區，與每筆明細的附註分開保存。
- 範例稿內的客戶、品名、價格、數量和文字只作測試 fixture，不作 seed 或預設值。

### 3.3 報價列印

- 使用 A4 橫向版面。
- 必須包含公司抬頭、客戶資料、報價號碼／日期、完整明細欄及文件備註。
- 不列印建檔頁的另存新檔、存檔、取消、列印按鈕，也不以瀏覽器輸入框外觀呈現正式文件。
- 以空白稿與範例稿各做一組 snapshot，再用公司實際印表機檢查裁切、字級、欄寬與跨頁。

## 4. 工單建檔契約

### 4.1 單頁與基本資料

- 工單建檔是同一張整合表單，不拆成材料、印刷、製程 wizard；桌面可用頁內導覽，窄螢幕依序單欄排列。
- 頁首與頁尾都依公司稿提供「另存新檔、存檔、取消、列印」，兩處動作必須呼叫相同的正式 command／validation。
- 客戶區包含客戶編號、客戶訂單號、客戶名稱、電話、聯絡人及地址；選客戶後自動帶入並在確認時保存快照。
- 工單區包含工單號碼、訂單日期、交貨日期、品名、訂單數量、訂單內容／規格補充、單價、版費及刀模費。
- 訂單日期預設公司當日且允許修改；單價至少顯示兩位小數。
- 註解稿顯示舊候選為「日期＋3 碼流水」，例如 `260427001`；使用者後續已在 P0-09／ADR-018 簽認新版 `WO-YYYYMMDD-SSS`，舊號仍原樣顯示與搜尋。
- 附件呈現一組主要品名與數量；P0-02 已由公司另行定案為一張工單一個主要成品，同訂單其他品項放在同案件的其他工單。

### 4.2 備紙資料

| 材料 | 欄位 |
|---|---|
| 面紙 | 供應商、紙質、廠別、尺寸、數量、備註 |
| 底紙 | 供應商、紙質、廠別、尺寸、數量、備註 |
| 浪紙 | 供應商、紙質、尺寸、數量、備註 |

- 公司稿明確顯示面紙與底紙有廠別，浪紙畫面沒有廠別；正式新建檔頁依這個 type-specific 契約呈現。
- 供應商、紙質及適用廠別由主檔選取；不得把範例稿的供應商或紙名寫成固定選項。
- 舊資料若有浪紙廠別，Import 仍須保留原值與來源，不代表新建檔畫面要自行增加欄位。

### 4.3 印刷規格

- 印刷尺寸長／寬、K 數、模數、印刷數量及加減量。
- 正面與反面分別保存色數、C／M／Y／K 勾選及可輸入多行的特別色。
- 保存總色數；CMYK 未由公司指定預設值，因此新建工單時不得預勾 K 或其他色。
- 附件中的 checkbox 圖示標為「樣式範例」，只用來決定多選控制元件，不代表新增「顯示／列印」業務欄位。

### 4.4 製程資料

正式建檔順序固定為：

1. 美工
2. 輸出
3. 製版
4. 打樣
5. 印刷
6. 上光
7. 裱紙
8. 模具
9. 軋型
10. 加工
11. 糊邊
12. 運送
13. 其他

共同規則：

- 每一道製程依公司稿保留協力廠與內容／說明。
- 協力廠、上光類型等可管理選項來自主檔；「其他」仍允許協力廠查找加自由文字。
- 附件沒有明示每道製程需要數量、單價、「是否需要」或「是否顯示／列印」欄位，因此不得自行加入正式 schema。

專屬規則：

- 製版：新版／舊版為一組單選，天地／左右輪轉為另一組單選；兩組無預設且可留空，不得合併成四選一。
- 上光：提供上光類型主檔選取。
- 軋型：保存刀模號碼與模數。
- 糊邊：保存盒／袋選項。
- 其他：協力廠查找與自由文字內容。
- 註解 PDF 中的 radio／checkbox 圖只標示「樣式範例」；除了附件明確連到的製版與 CMYK 外，不推導額外流程規則。

### 4.5 備註、圖片與列印

- 工單整體備註允許空白，輸入元件至少能容納 150 個中文字；這是容量需求，不是要求使用者至少輸入 150 字，也不自行設定 1,000 字上限。
- 支援工單圖片附件；正式檔案採私人儲存、授權下載、類型／大小／雜湊檢查與軟刪除。
- 工單列印使用 A4 直向，包含公司抬頭、工單號碼、日期、客戶與訂單、品名與數量、三種備紙、正反面印刷、備註及附圖。兩份列印稿固定顯示 9 個製程列：製版、打樣、印刷、上光、裱紙、軋型、加工、糊邊、其他；建檔頁完整 13 道中的美工、輸出、模具與運送未出現在列印稿，不得自行宣稱列印完整 13 道。
- 列印樣張內的勾選、客戶、品名與數值只作驗收案例；主檔日後修改不得改變已確認工單的文件快照。

## 5. 查詢、刪減與備份契約

- 工單查詢增加較細的關鍵字範圍；至少可覆蓋工單號、客戶單號、客戶名稱／簡稱、品名、備註、刀模號碼、特別色及製程說明。
- 查詢結果增加單價、版費及刀模費欄位。
- 不建立獨立色別設定與裁紙設定頁；工單內的 CMYK、特別色與備紙欄位仍保留。
- 備份必須同時有公司持有的雲端備份與公司硬碟備份，並以完整還原演練驗收，不能只驗證備份檔存在。

## 6. 尚未由附件定案的邊界

| 項目 | 原因 | Gate |
|---|---|---|
| 報價與工單附件號碼與新版差異 | 附件提供無前綴範例；P0-09／ADR-018 已另行簽認七類新號及舊號原樣保留 | Phase 3～8 單號與 Import 回歸 |
| 各欄位必填、最大字數及預設勾選 | 附件未完整標示 | 對應 Slice 開始前補 UAT 規則 |
| 浪紙舊資料的廠別去向 | 新稿無此欄但既有整理可能有歷史值 | Import mapping／公司抽樣簽認 |
| 工單列印是否擴充為完整 13 道製程 | 列印稿固定 9 列，與建檔頁 13 道不同 | Phase 4 列印 Slice 前公司簽認 |

## 7. 開發與驗收使用方式

1. 開始 Slice 3.x 或 4.x 前，先以本文件和 `docs/需求追蹤矩陣.md` 建立測試案例。
2. 實作一個 Slice，只驗證該列欄位、狀態、API 與列印責任，不把整張表單塞進單一元件。
3. 空白稿驗欄位與排列，註解稿驗規則，範例稿驗輸入／輸出，列印稿驗紙張與快照。
4. 每項驗收證據寫回 `docs/progress/實作進度紀錄.md`；未通過不得把該 Slice 標成完成。
5. 頁面樣稿和附件格式不能取代 P0 決策、後端驗證或資料庫約束；P0-01／P0-02 的案件模型以 ADR-014 為準。
