| ADR-018 | 七類新單使用英文前綴與日／月流水；舊號原樣保留可搜尋 | 新舊資料可辨識又不改寫歷史鍵 | 實際單量接近當日／月位數上限 |
| ADR-019 | 有效運送完成後可由專用權限者同交易補登真實完工再出貨，永不負庫存 | 保留舊操作便利又維持可重建、可稽核的庫存流水 | 公司取消運送前置或改變完工／出貨責任 |
| ADR-020 | 瀏覽器登入採 HttpOnly Session Cookie＋Session-bound signed double-submit CSRF＋exact public Origin | raw token 不暴露給 React／JSON，並同時防止跨站與 Cookie 注入型 CSRF | 改為跨來源部署、全面本機 HTTPS 或導入不同身分供應者 |

完整 ADR 若改變核心方向，建立在 `docs/decisions/`。

## 3. 風險處理規則

- 高影響且高可能性的風險不得只寫「之後注意」，必須對應 Slice、測試或待確認項目。
- 風險發生時在進度紀錄寫事件、影響、暫時處置及長期修正。
- 關閉風險需有證據，例如測試、簽認、還原報告或量測結果。
- 新風險若會改變架構，先新增 ADR，再修改程式。
