# 需求追蹤矩陣

> 目的：確保每一項公司需求都有來源、實作位置、計畫 Slice 與驗收方法。新增需求必須先加入本表。

來源代碼：

- `FLOW`：影片、Private & Shared 實際操作流程。
- `GMAIL`：公司 Gmail 新需求與版面註記。
- `LEGACY`：舊 PowerBuilder 原始碼、介面及資料關聯。
- `DESIGN`：為安全、追溯或可維護性提出的新版設計；需要時由公司確認。

## 變更規則

- 新需求沒有 ID，不得直接實作。
- 修改需求語意時保留原 ID，更新版本與決策紀錄。
- 完全不同的新需求建立新 ID。
- 標記完成前必須填入實際測試或 UAT 證據位置。
