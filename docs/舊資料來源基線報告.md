## 1. 盤點方法

- 來源：專案外層 `../extraction/export/uv_print_full/tables/`。
- 工具：`scripts/legacy_import_profile.py`。
- 每個 CSV 記錄檔名、SHA-256、實體行數、CSV 邏輯筆數、欄位數、第一欄鍵值統計，以及編碼異常的彙總數量。
- 報告不保存客戶名稱、地址、電話、統編或任何業務資料列內容。
- 輸出位置在被 Git 忽略的 `artifacts/import/`；工具會拒絕把報告寫回來源目錄。
- 同一來源連續執行兩次，兩份 JSON 報告逐位元一致。

「可用 UTF-8 解碼」不代表文字完整。來源內已存在大量 `U+FFFD` 與控制字元，其中 `sal.csv` 最嚴重；正式 Import 必須保留原始 bytes／來源雜湊、記錄清洗原因，不能把異常字元靜默刪除。

## 3. 客戶資料 `cust.csv` 結論

| 指標 | 結果 |
|---|---:|
| 實體行數 | 225 |
| CSV 邏輯行數（含表頭） | 222 |
| 客戶資料列 | **221** |
| 唯一第一欄鍵值 | 221 |
| 重複第一欄鍵值 | 0 |
| 空第一欄鍵值 | 0 |
| 欄位數不一致資料列 | 0 |
| `U+FFFD` | 109 |
| 控制字元 | 168 |

先前出現 221／222 的原因已定案：**221 是客戶資料筆數；222 是包含表頭的 CSV 邏輯行數。** 實體行數為 225，是因為部分欄位內容帶有內嵌換行，不能用一般逐行計數作為資料筆數。

## 5. 重跑方式

```bash
make import-profile \
  PYTHON=/path/to/python3.12 \
  IMPORT_PROFILE_OUTPUT=artifacts/import/profile
```

重跑後應檢查：來源檔案 SHA-256 是否不變、報告是否可重現，以及異常數量是否與本基線一致。
